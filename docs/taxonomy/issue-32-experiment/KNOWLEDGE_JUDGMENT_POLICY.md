# 分類判断原則：設問の題材ではなく、命題の判定に必要な知識を分類する

対象: Issue #32 の v1.1 分類、PR #33 の2005〜2025年度命題データ。既存の4大分類と固定ノードIDを変更しない。

**現在の状態**：PR58の88設問・236命題の修正は、全年度の `propositions/YYYY.jsonl` に統合済みです。設問別オーバーレイは残っていません。集計・難例一覧・チェックサムを更新し、PR39の校正文も同期しました。現在の件数は [README](README.md) とmanifestを参照してください。以下で「このPR」「原文・manifestは未変更」と記す範囲はPR58作成当時の履歴です。

## 原則

**「この命題が正しいか誤りかを判断するには、どの知識を取り出せばよいか」**を先に特定する。選択肢に登場する職種・施設・疾病名、設問の章立て、文章の文法上の主語は、分類を決める十分条件ではない。

ここでいう「判定」は*知識の特定*であって、真偽や最新法への適合性を確定することではない。**誤った命題も、その誤りを判断するための知識に分類する。** 年度別の法令・原文/OCR・正答は別工程で確認する。

## レビューフロー

1. **文脈を補う。** 設問文と選択肢を読んで「何が何である／何を行う／何を要求されるか」という独立命題を把握する。原文 `source_text` と設問文 `question_stem` は変更しない。複数の独立事実なら命題分割を検討する。
2. **判定知識を一文にする。** 例：「介護予防支援事業者のサービス担当者会議には、どんな法定開催要件があるか」。これを `knowledge_target_review.needed_knowledge` に記録する。
3. **題材と知識を切り分ける。** 例：「設問にグループホームが登場するが、選択肢の正誤はADLの把握方法で判断する」。題材を `context_not_decisive` に残す。
4. **固有性を確かめる。** 別のサービス・職種・利用者の例でも同じ考え方で判断できるなら、汎用の方法・原則（2）等に置く。ただし、特定の施設・事業者・機関に課される法的要件や固有の提供内容はその概念（3）、制度共通の資格・給付・権限は制度（4）に置く。疾患固有の病態・ケアは疾病（1）、一般的な支援技法は（2）に置く。
5. **正本を一か所にする。** 選んだ `primary_node_id` は存在するv1.1の固定IDにし、詳細属性は `primary_path` と `attribute` に持つ。題材として重要な施設・疾患・資源は `related_concepts` で参照する。
6. **境界は無理に解消しない。** 判定知識を特定しても本当に複数の正本が競合する場合は `ambiguous` と候補・理由を維持する。`assigned` は意味・真偽・法令の検証完了ではない。
7. **変更理由を追跡する。** `classification_reason` に判定知識と題材より優先した理由を残し、`knowledge_target_review` に旧経路・主語・属性を保存する。`classification_revision.additional_reviews` に今回のレビュー履歴を追記する。既存の履歴や出典メタデータは上書きしない。

## 全件スクリーニングと意味レビューの区別

### 2026-10-11追加

- `node scripts/audit-issue32-all-propositions.mjs --output-dir=./issue32-audit-output` は、**21年度・6,346命題を1件も漏らさず走査**し、各命題について設問文・命題・分類先・判断対象を記録する。
- CI `Validate taxonomy metadata` が `issue32-full-classification-screen` の名前で**全6,346件のJSONL＋年度別集計**をGitHub Actions artifactに保存する（30日間）。
- 明示的な「判定知識レビュー」の履歴があるのは**236命題**。残り**6,110命題は、このレビュー方式で意味検証済みではない**。過去の `classification_review` が存在しても検証が十分だったと自動認定しない。
- 初期の分類保留25件は解消し、実効データの `ambiguous` は0件。ただし、`assigned` は**分類されたという状態**で、分類の正しさや試験の真偽の保証ではない。
- 登録済み固定ノードIDが欠落する命題が**3,271件**。既存のID整理と重複調整なしに、近そうな親ノードを機械的に当てはめることはしない。
- `primary_path` が固定ノードのラベルと一致しなくても、元の詳細名・同義語の場合は誤分類とは限らない。IDの存在・ルート矛盾・名称の別表現を分けて報告する。
- 全件スクリーニングで正誤判定に不要な題材が疑われるものは、**確定エラーではない**。目視・意味判断が必要な候補として台帳に残す。ルールに一致しなかった残りを「合格」にはしない。

### 対象外の確認

今回は過去問の**正答・原文・OCR・法令の当時適用の検証ではない**。特に旧法の条文、経過措置、指定基準・報酬改定時点などの正誤判定は別タスクである。分類先の判断は、真偽の確定がなくても「どの知識で判定できるか」を対象に行う。

### 最終的な全件検査の読み方

- 2026-10-11の最終CIで、意味分類の変更・確認履歴は **236命題 / 88設問**。実効データは6,346件・うち分類保留0件。
- `primary_node_id` の未設定は **3,271件**。別名・詳細名によるパス表示の差は16件で、必ずしも分類ミスではない。
- 判定知識レビュー未実施は **6,110件**。既存ルールにヒットする**未レビューの機械的疑義候補は0件**だが、ヒューリスティクスの網羅性・意味分類の妥当性を保証しない。既に判断知識を個別レビューした6件は文面上の特徴により機械的フラグが残る。
- 「未レビューの疑義候補0」は、全6,346命題の正誤や意味分類が承認済みであることを意味しない。分類木の学習用正本化には別途、未レビュー行の意味レビューが必要。
