固定5大分類・28中分類の下に221小分類案を設計し、年度正本の命題を個別監査している。分類案は一次資料と既存命題の照合によるアプリの設計判断。大分類・中分類のID・名称は変更していない。

## 正本と変更方法

現在の分類正本は年度JSONL内の `taxonomy_assignment`。そこに概念・属性ID、所属、理由、入力フィンガープリント、移行方法、要確認フラグを保持する。旧 `primary_path`・`drawer_assignment` は移行前の分類とレビューの履歴で、アプリの所属を決定しない。旧ID正規化スクリプトはその履歴の監査用。別ファイルに命題別の編集判断は置かない。

原文・命題・ID・正答・出題当時の情報・既存レビュー履歴は保存した。新しい指紋検証により、判定知識や元入力を変えたまま移行判断を放置すると生成を拒否する。

- 新分類の修正：当該命題の `taxonomy_assignment` を更新し、`method: individual_review`・理由を記録する。元入力の変更時は指紋も再確認する。
- `migrate-issue32-5x28.mts --write` は初回移行／規則検証用。個別判断を追加した後の一括再実行で上書きしない。
- `npm run prepare:questions` は年度正本から生成し、移行規則を再適用しない。設問別修正にも同じ分類を持たせ、統合前の表示にも反映する。
- 集計再生成：`node --experimental-strip-types scripts/report-issue32-5x28.mts`。その後に既存の統合・チェックサム生成を実行する。
